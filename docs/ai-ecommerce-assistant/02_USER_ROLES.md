版本：v1.0 · 2026-09-11。状态：产品与工程规格；应用尚未开发。P0为本次定义的开发范围，P1/P2只作规划。

# PART 2｜用户角色和权限

P0 不引入完整可配置 RBAC。四种固定角色使用服务端能力映射，Membership 只存一个角色；Owner 单人，组织内成员默认能访问其角色允许的所有店铺。没有店铺隔离需求的试点才能采用此模型，有强制店铺隔离需求的企业暂不纳入该版本。

| 权限 | Owner | Admin | Operator | CustomerService |
|---|---|---|---|---|
| 查看经营数据与广告 | 全部 | 全部 | 全部 | 禁止，包括首页聚合和报表导出 |
| 查看商品数据 | 全部 | 全部 | 全部 | 仅客服记录关联的 SKU 名称/编码，不含经营统计 |
| 查看客服数据 | 脱敏数据 | 脱敏数据 | 脱敏数据 | 脱敏数据 |
| 导入数据 | 全部 6 类 | 全部 6 类 | 全部 6 类 | 仅 customer_messages |
| 修改原始业务数据 | 禁止直接编辑；更正重导 | 同左 | 同左 | 仅可重导客服消息 |
| 修正 VOC 人工标签 | 允许，审计 | 允许，审计 | 允许，审计 | 允许，审计 |
| 查看 AI 建议 | 全部业务 | 全部业务 | 全部业务 | 仅客服建议及客服证据投影 |
| 修改行动状态 | 自己的状态 | 自己的状态 | 自己的状态 | 自己的客服建议状态 |
| 修改店铺、数据源、AI/规则配置 | 允许 | 允许 | 禁止 | 禁止 |
| 邀请成员 | 可邀请 Admin/Operator/CustomerService | 仅 Operator/CustomerService | 禁止 | 禁止 |
| 管理权限 | 可修改非 Owner 成员角色 | 仅管理 Operator/CustomerService，不可操作 Owner/Admin | 禁止 | 禁止 |
| 管理组织基础信息 | 允许 | 允许 | 禁止 | 禁止 |
| 删除组织/转移 Owner | P0 不提供入口/API | 禁止 | 禁止 | 禁止 |

最小实现：Better Auth 数据库 session 识别 User；服务端读取 Membership 得到组织和角色，再校验目标 Store 属于同组织。请求中的 `org_id` 不能决定权限；组织/店铺切换只切换显示上下文，所有查询、任务、缓存和下载仍需校验。服务端拒绝跨组织引用；前端隐藏入口只是体验措施。

CustomerService 登录默认进入客服中心，不能请求全量 Dashboard 再在浏览器隐藏金额。客服建议必须由服务端先筛选授权的 VOC/FAQ/售后计数证据，再单独生成或构建独立受限视图；只要结论、标题、SKU 描述或证据包含经营金额/销量/广告信息，即不得向该角色返回。日报、搜索结果、异常数量、趋势接口、文件名、错误下载和导出都遵循相同边界。混合证据建议整条不返回，不能仅删去 `evidence` 留下泄露财务的摘要。

初始 Owner 由部署初始化流程建立；系统不提供公开注册。邀请链接仅生成，不自动发送，单次使用、48 小时有效；失效或已使用显示重新申请入口。角色变更和成员禁用即时影响下一次服务端请求；导入提交、任务执行及下载签发重新鉴权。审计记录操作者、组织、动作、目标、时间及必要变更，不记录密码、客户原文或密钥。
