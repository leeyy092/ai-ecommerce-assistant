# 开发任务与依赖

版本：v1.0 · 2026-09-11。状态：产品与工程规格；应用尚未开发。P0为本次定义的开发范围，P1/P2只作规划。

# PART 20｜开发任务拆解

**目标：**让受邀企业用标准CSV完成一次真实数据导入，在一页看到可信经营摘要、异常和有证据的人工行动建议。**架构：**同仓库Web/Worker、统一Adapter、PostgreSQL版本快照。**技术栈：**严格按PART14。**规格：**执行前阅读本文件夹01—11，进度只写12_PROGRESS.md。

这是开发计划，不代表任务已执行。每次会话只完成一个TASK；先确认依赖已验收。每个任务完成后执行该项测试与类型检查，更新进度，记录命令、结果和产物。不要求给低影响文档或样式改动另造单元测试，但该TASK仍须运行相关已有测试或可复核检查。

全局禁止：未经需求明确授权实现P1/P2、替换技术栈、增加大依赖、重构无关模块、在客户端计算财务口径、通过LLM计算指标、把Mock与真实数据混用、擅自发布外部系统。下表各TASK的“禁止修改”是在这些全局约束之外的局部边界。

共同小步骤：①读指定输入与依赖验收；②补一个能验证目标的失败用例或契约检查；③完成限定修改；④执行列明测试及 `pnpm typecheck`；⑤只将已通过内容记入12_PROGRESS.md，失败则写blocked原因和复现步骤。不在本规格里提供应用实现代码，符合本次“先不要写代码”的要求。
